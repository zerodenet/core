# Repository Guidelines

## Structure

Root `src/main.rs` builds the `zero` binary and is limited to process initialization, tracing, error exit, and application executor invocation. `src/application/` owns command execution split into run, inspect/status, control IPC, and TUN control responsibilities. Reusable crates live under `crates/`. External protocol implementations live under `protocols/`.

### Crates (dependency bottom-up)

- `zero-traits` — `#![no_std]` runtime-neutral abstractions: protocol traits (`TcpTunnelProtocol`, `UdpRelayProtocol`, `UdpPacketPath`, `DatagramCodec`, etc.), `TransportKind`, `InboundTransport`, address types, async socket/listener traits. No runtime dependency.
- `zero-core` — runtime-neutral domain primitives, request/packet facts and component identities, including `Session`, `Address`, `Error`. Depends on `zero-traits` and remains `no_std`.
- `zero-api` — interface contract types (snapshots, commands, events). Independent.
- `zero-config` — config ADTs (`RuntimeConfig`, `InboundConfig`, `InboundProtocolConfig`, `OutboundProtocolConfig`, `RouteConfig`, etc.), structural/reference validation, and delegation to validation-only protocol APIs for protocol-private values. Depends on `zero-api`, `zero-router`, and the lightweight validation surfaces of relevant protocol crates.
- `zero-router` — rule set matching and route decisions. Depends on `zero-core`.
- `zero-engine` — the control kernel: engine plan, target resolution, session registry, stats, event log, hooks, groups (urltest/selector), outbound health. Depends on `zero-api`, `zero-config`, `zero-core`, `zero-router`.
- `zero-logging` — non-blocking structured logging with event bridge. Depends on `zero-config`.
- `zero-dns` — configurable DNS resolver, caching, fake-IP, routing. Depends on `zero-config`, `zero-platform-tokio`, `zero-traits`.
- `zero-platform-tokio` — tokio runtime implementation of the traits abstractions (`TokioSocket`, `TokioListener`, `TokioDatagramSocket`, `TcpRelayStream`, `ClientStream`, `TransportConnector`). Public runtime collaboration contracts live in `contract`; this crate depends on `zero-traits`, `zero-core` and `zero-error`, never config, engine, proxy or concrete protocols. Core/traits stay `no_std`.
- `zero-transport` — concrete carrier implementations (QUIC, TLS, WebSocket, gRPC, H2, HTTP-Upgrade, split-HTTP, REALITY) and neutral I/O wrappers. Protocol-private transport plans remain protocol-owned. It must not import or project `ResolvedLeafOutbound`; engine-leaf projection belongs to owning proxy adapters. Feature-gated per transport. Depends on `zero-core`, `zero-error`, `zero-platform-tokio` and `zero-traits`, never config, engine, proxy or concrete protocols.
- `zero-runtime` — common component catalog, resource generations, lifecycle/task ownership, confirmed shared-resource replacement, prepared routing/configuration resources, source persistence/recovery and configuration-operation ownership. Depends on config/core/platform/traits; never on proxy or concrete protocol runtimes in production. Proxy injects its actual factory registry and publication-receipt type.
- `zero-proxy` — the orchestration layer: `Proxy`, `ProxyHandle`, `RunningProxy`, reload/reconcile, `ProtocolRegistry` capability dispatch, protocol-local inbound listener entrypoints, `serve_inbound` unified TCP pipeline, TCP/UDP dispatch, upstream connect helpers. Depends on runtime/config/core/dns/engine/platform/traits/transport/tun/stack.
- `zero-connector` — event dispatcher and outbound sink delivery. Optional (`event-dispatcher`, `sink-jsonl`, `connector` features).
- `zero-connector` provides controller-neutral event delivery. A controller registers a webhook by applying `api.event_sinks` through the existing Zero API over HTTP/IPC/gRPC. Connector sends the `zero.event.v1` envelope to the complete configured URL, applies only the documented HTTP acknowledgement classification, and owns retry/outbox/dead-letter delivery state. It must not prescribe receiver paths, node registration, synchronization, presence, traffic endpoints, authentication schemes, panel workflows, user/plan/billing models, inbound/protocol configuration, or a second command/configuration API. Direct management uses `zero-api`, HTTP/IPC, or gRPC. External systems adapt to Zero or run an external compatibility bridge; Zero contains no third-party dialect or public adapter SPI.
- `api.event_sinks` is a zero-to-many delivery-channel registry. `tag` is only the node-local sink/status/outbox identity, `url` is a complete receiver address that registrations and nodes may reuse, `events` is the event-type capability filter, and `source_id` is optional envelope metadata. Webhooks must never be bound or selected by node identity, inbound, credential, or proxy protocol. External systems own decisions such as limiting, disabling, upgrading, and notification; they use generic Zero API/gRPC/configuration methods where applicable and keep deployment upgrades outside Connector. Connector only converts, filters, and reliably delivers kernel events.
- `zero-grpc` — gRPC control plane adapter. Optional (`grpc-api` feature).
- `zero-ffi` — C-compatible FFI bindings.
- `zero-tun` — platform-agnostic TUN device abstraction.
- `zero-stack` — user-space network stack (TCP termination + UDP forwarding from raw IP packets).
- `zero-ztls` — generic TLS 1.3 client with custom ClientHello (extracted from REALITY).

### Protocols

External protocol implementations under `protocols/`: `socks5`, `http`, `vless`, `hysteria2`, `shadowsocks`, `trojan`, `vmess`, `mieru`, `wireguard`. Runtime-neutral surfaces use `zero-core` and `zero-traits` plus protocol crypto. Optional runtime features may consume platform contracts and generic transport carriers without depending on config, engine, proxy or the runtime host; validation-only consumers must not enable these runtime modules. Proxy assembly selects actual component factories and the remaining executable compatibility capabilities.

Protocol package versions track the explicitly selected upstream implementation version one-to-one; they do not inherit the Zero product version. Compare feature completeness against that exact upstream tag and immutable commit, not the latest release. Keep package/lockfile versions, reference documentation, default interop tooling and baseline CI consistent. A deliberate reference upgrade must update those surfaces together. Additional-version interoperability is supplementary evidence and must not silently redefine the implementation baseline. A matching version number does not itself prove feature completeness. RFC-only protocols have no upstream implementation release to mirror.

### Key paths

- `AGENTS.md` — versioned engineering guidelines and architecture boundaries.
- `release/breaking-changes.md` — versioned release compatibility ledger.
- `docs/` — optional local notes, ignored by Git; never a build or CI dependency.
- `examples/` — example configs, versioned.
- `tests/` — binary-level integration tests.
- `crates/proxy/tests/` — proxy-level integration tests (protocol interop, session observability).

## Features & Build

Default build is `--features full,status-api`. Optional features:
- `socks5`, `http`, `mixed`, `vless`
- `hysteria2`, `shadowsocks`, `trojan`, `vmess`, `mieru`, `dns`
- `status-api` enables runtime control endpoint and selector switching
- `event-dispatcher` enables generic event delivery, `sink-jsonl` enables the local JSONL sink, and `connector` enables webhook delivery
- `connector` does not imply `status-api` or `grpc-api`; control transports are selected independently
- `grpc-api` enables the gRPC control plane adapter
- `host-network-stats` enables read-only host interface statistics on supported platforms

If a config references an uncompiled protocol, it fails early with a clear error.

## Commands

Always use workspace-wide commands by default:
- `cargo fmt --all`
- `cargo check --workspace`
- `RUST_MIN_STACK=16777216 cargo test --workspace --all-features` (full test suite; matches CI feature coverage and 16 MiB test-thread stack)
- `cargo clippy --workspace --all-targets`
- `cargo build --release`
- `cargo run -- run <config>` - run proxy with given config
- `cargo run -- status [--json] <config>` - show current status

Run a single test: `cargo test <test_name>`

If you change protocol behavior, config parsing, routing, or runtime wiring, run the full test suite.

## Style

- Use `rustfmt` defaults
- Keep module/function names `snake_case`, types `CamelCase`, packages `zero-*`
- Prefer ASCII, keep directory names short
- Split files around 300 lines

## Tests

- Tests live in sibling `tests/` directories, not inline in logic files
- Name tests after the behavior they test
- Always add/update tests when changing config shape, protocol handling, routing, runtime behavior, or logging
- Listener fixtures retain the actual bound socket until its worker takes ownership. A shared port-allocation mutex does not reserve endpoints against the OS or other processes.
- Cleanup regressions consume the original native controller's close receipt and verify its transferred view is retired. Post-close port availability is not evidence of that original handle's close outcome.
- Cancellation regressions establish that the actual awaited operation is still pending at an explicit I/O suspension point. A child PID marker or delay alone does not establish pending readiness; retain real child spawning, ownership and reaping assertions, and never fabricate successful probes.
- Listener fixtures invoke the same host request_stop and full observer as production before awaiting native peer retirement. Sending the listener watch alone does not revoke the original peer scope; neither notification is a close receipt. Retain original controller and Scope join assertions.

## Boundaries

- One `zero_runtime::RuntimeHost<A>` owns the assembled component catalog, configuration task owner, serial apply lock and pending acknowledgement. `ProtocolRegistry` owns lookup/dispatch only; inventory and proxy clones share the same host. Weak dispatch references must not retain the host or its pools. Host Debug must not expose pending configuration snapshots.
- Shared/native replacement closes affected current owners and their transitive consumers before building a candidate. Transferred Stream/Datagram uses charge the actual shared-resource generations, including users of historical role handles. Keep only lightweight counters/cancellation there, not old configurations or a per-session task/registry. Cached fenced role handles retain weak protocol-role references so they cannot pin retired private resources. Ending a user lease proves custody ended, never native close; a complete slot still requires actual protocol, TaskScope and original provider evidence. An incomplete consumer also blocks cleanup of its dependencies.
- Background carrier borrowing is opt-in through Stream/Datagram carrier roles. Persist the real logical LoanOwner before awaiting preparation, keep its actual original slot/driver lineage, and distinguish logical return from donor native close. Same-owner Mieru prefixes share the actual adapter pool and Scope; cross-owner replacement dependencies and actual Proxy native DNS query providers remain admission gates. Network/DNS transitions may not acquire new carriers until old originals and transferred logical user/control debts have settled. Ordinary Mieru production registration stays closed until the complete gate qualifies.
- Only native declarations with integrated original-close providers and supported role executors may activate in the ordinary catalog. Roleless protocol resources use the same retained lifecycle and TaskScope as callable roles. Unsupported process/device/ICMP/background native ownership remains rejected; a declaration or protocol-only report cannot substitute for provider evidence. Shadowsocks native TCP without plugins shares the owning adapter's actual replay state; SIP003 outbound and other remaining legacy paths retain their explicit compatibility ownership; inbound plugins use the standard source host described below.
- Cold assembly validates host-assigned dependency identities, duplicate entries and cycles before build/start. Start follows dependency order and protocol cleanup follows reverse order. Ordering alone does not prove transferred sessions or shared I/O have closed; resourceful replacement still requires the host's confirmed cleanup and recovery transaction.
- Canonical shared-resource preparation uses typed neutral recipes and the real host allocator. One assembly namespace identifies one owning factory/state; equal static identities must also have equal complete descriptions. A failed consumer, allocation or graph validation invalidates the entire cold pass; discard it before preparing again. These recipes use the same persistent lifecycle/task owner as ordinary roles and must not activate resourceful production factories before host replacement confirmation exists.
- Cold reuse compares actual dependency generations in topological order and advances each affected consumer once, while unchanged nodes retain their actual role owners. A canonical identity index belongs to one host allocator and compiled assembly; retain only namespace, secret-free identity and ComponentId, never previous recipes/factories. Metadata reclamation does not prove protocol-owned history, pools or I/O have retired.
- Resolve declared dependencies to actual ComponentInstanceId values before build; the erased boundary rejects missing, extra, duplicate or wrong identities before invoking the factory. Roleless owners need no invented RoleId. Immutable dependency bindings are a planning snapshot, not a current-generation admission fence or proof of user/I/O cleanup.
- Component factories declare their internal task limit explicitly; `None` grants no tasks. Install the resource owner before awaiting start, retain it when start is interrupted, and drive protocol cleanup together with scope cancellation and joins. Interrupted cleanup must retain collected task failures and their sources. Timeout, abort and Drop never prove resource closure.
- Shared Shadowsocks TCP2022 replay maintenance uses the actual adapter-scoped salt pool. Its native roleless factory declares one critical task, joins any legacy worker before registration, and keeps the maintenance lease until the registered future exits. Protocol cleanup alone cannot admit a replacement worker; valid salt history and capacity rejection survive retirement. Activate resourceful factories only after host shared-resource planning and confirmed replacement ordering exist.
- SIP003/SIP003U inbound plugins use the same standard ComponentFactory/InboundSource/Stream/Datagram as native Shadowsocks. A neutral ListenerHandoff declaration retains the public TCP reservation and same-family kernel loopback originals in one installed host; consume the real public close report before spawning the carrier. The actual Child is installed synchronously through the finite start-only Process grant before readiness can suspend. One Critical monitor lives in the same Scope; cancelled/failed readiness is terminal and retains that original Child through actual reaping. Readiness owns the real PendingTcpConnect controller, confirms it before another attempt, and uses a pure local-service selection without an unowned UDP route probe. SIP003U adds no fabricated UDP readiness handshake. Child reaping, kernel listener/accepted/datagram originals, transferred users and Scope joins are separate gates; direct-child completion does not assert descendant containment or qualify ordinary catalog process resources. The old inbound carrier SPI, TCP/UDP compatibility executor, TCP listener dispatcher and InboundConnectionContext tree are removed. TCP2022 sources reuse their actual acceptor salt pool and existing replay Owner in that same Scope, preventing a legacy maintenance worker from starting beside it.
- SIP003 outbound plans install their Child owner before awaiting readiness. Once a Child exists, failed or interrupted readiness is terminal for that plan and retains the original failure or child handle; cancellation requests termination without claiming exit. The protocol resource handle shares the adapter's actual plan and exposes deadline-bound shutdown with a reaped ExitStatus; interrupted/expired cleanup retains ownership. Native process grants and host replacement transactions must use that actual owner, never a dummy SessionOwner or a Drop-based completion claim.
- Native process access declares an executable and an explicit finite start budget for one component generation. The real host slot denies spawning during build and outside its bounded lifecycle start phase; synchronous spawning lets the persistent protocol owner install the actual Child before any await. Native SS plugin owners share the adapter plan, reject adoption of a legacy-owned child and register their real monitor in TaskScope. Reaping a direct child is not descendant containment, transferred-user/I/O closure or permission to activate resourceful production factories before confirmed host replacement exists.
- Compiled component factories and remaining capability adapters share the state from one assembly. Bound carrier-health observations retain weak generation identities and kernel references; historical configuration snapshots and Engine ownership must not escape into retained upstream openers. Protocol request framing consumes destination facts; internal Service/prefix operations never invent a business SessionId.
- Do not move protocol parsing into root binary
- Do not construct control or TUN IPC requests in `src/main.rs`; command semantics belong to `src/application/{control,tun,inspect,run}.rs`.
- Keep `crates/engine/src/runtime.rs` as the construction/mode/route facade. Engine configuration snapshots, policy state, observability projection, diagnostics, and session lifecycle belong to `runtime/{configuration,policy,observability,diagnostics,session}.rs`. Resource preparation and source persistence/recovery belong to `zero-runtime::configuration`; Proxy coordinates them under the existing RuntimeHost ApplyOwner. Engine-only/FFI entrypoints retain their existing scope without starting a Proxy.
- Pure route evaluation and the decision to request resolved IPs live in `crates/engine/src/runtime/route.rs`. Proxy consumes that evaluation and owns asynchronous DNS execution; it must not duplicate bypass matching or mode precedence.
- Keep raw packet parsing/building pure in `crates/stack/src/packet.rs`; async TCP/UDP connection lifecycle consumes that boundary from sibling modules and must not recreate IP parsing.
- ICMP Echo source translation is an explicit Packet adapter: pure address/checksum/error-quote rewriting stays under `zero-stack::packet`, bounded correlation stays in `zero-stack::echo_translation`, and neutral raw-IP device modules own I/O and return channels. `route.mode=translate` uses existing TCP/UDP Flow conversion plus the selected PacketSink's opt-in address adapter. Do not add an ICMP Flow plane or put Echo correlation in WireGuard or the router; native `auto`/`packet` forwarding preserves source addresses and strict `flow` remains TCP/UDP only.
- Raw-IP datagram inbounds use the standard ComponentFactory/InboundSource/AcceptedRequest::Packet contract. Neutral `runtime/inbound_operation/raw_ip/{source,wire,run}.rs` separates the real granted wire driver from host Packet routing, stack and shutdown lifecycle. WireGuard handshake demultiplexing, peer state, authentication, allowed-IP source checks, and key material stay in `protocols/wireguard`; its proxy adapter only projects validated config and maps opaque device actions into that neutral source. Do not dispatch WireGuard peers by outer UDP source address.
- Keep:
  - config ADTs and validation -> `crates/config`
  - routing -> `crates/router`
  - engine plan, session state, stats, events, groups, health -> `crates/engine`
  - reload/reconcile, protocol capability dispatch (`ProtocolRegistry`), protocol-local inbound listener entrypoints, `serve_inbound` pipeline, TCP/UDP dispatch, upstream connect -> `crates/proxy`
  - platform abstraction (socket, listener, stream) -> `crates/traits` + `crates/platform/tokio`
  - transport implementations (TLS, QUIC, WS, etc.) -> `crates/transport`
  - concrete protocol implementations -> `protocols/*`
- Protocol-private config fields (cert/key, cipher, identity/user IDs, etc.) are read from config by thin adapters or proxy transport bridges and parsed by protocol-owned constructors/helpers, never by the generic proxy runtime directly. Runtime code receives validated protocol values or opaque protocol/adapter-built keys, not raw protocol config strings.
- Trojan outbound password/TLS identity parsing follows the same rule: `protocols/trojan` owns TCP connect config, UDP flow resume, borrowed/owned TLS profile builders, and relay-TLS override resolution; proxy adapters only unpack leaf variants while transport bridges open transport streams through `zero-traits::ClientTlsProfile` instead of rebuilding Trojan TLS config inline.
- Port conflict detection is authoritative in config validation (`DuplicateInboundListen`); bind-time errors mean external port occupation only
- Listen-address literal parsing, endpoint formatting and canonical/wildcard overlap live in `zero-core::address`; proxy bind helpers consume structured IP endpoints and preserve hostname support. Keep OS-default IPv6-only behavior: `::` is not a portable dual-stack guarantee, and IPv4/IPv6 wildcard pairs on one port are rejected conservatively.
- Mieru transport option ADTs and validation live in the protocol-owned `protocols/mieru/config` (`mieru-config`) crate. Config and Mieru both consume it; do not introduce a `zero-config -> mieru/runtime -> zero-transport -> zero-config` feature cycle. Its version follows the same pinned upstream target as Mieru.
- Protocol-private validation is protocol-owned. Config may depend on validation-only protocol features and map their errors into `ConfigError`, but must not duplicate UUID/cipher/key/credential parsers or compile protocol data-plane modules for validation.
- `zero-engine::runtime` keeps domain configuration preparation/publication, policy state, and observability projection in `runtime/{configuration,policy,observability}.rs`. Config keeps ADTs and pure validation; it must not regain GeoIP/rule-set I/O or runtime compilation. Engine delegates original file ownership and persistence to the same ConfigurationSource and does not own cross-component transactions.
- `direct` and `block` target semantics stay inside `zero-engine`; socket-level direct execution stays in `zero-proxy`
- `mixed` is an inbound multiplexor, not an external protocol, but it is still registered through `MixedAdapter` so runtime code does not special-case it

## Control plane dispatch

- `ProtocolAdapter` must not exist. Standard protocol integration uses `ComponentFactory` and executable roles from `zero-platform-tokio::contract`. `ProtocolRegistry` retains `ProtocolSupportCapability`, standard inbound factory lookup and optional outbound projections. InboundListenerCapability, PreparedInboundListenerOperation, InboundDefinition, BoundInbound and the legacy prepare/bind/execute chain are deleted; do not recreate a replacement listener SPI. UDP cold constructors are bound statically at the adapter boundary; registered flows retain actual executable connections, never a global handler/provider set or an erased protocol payload. Do not restore empty TCP/UDP/packet-path marker traits or test-only capability objects. Outbound availability is determined by actual role handles or executable claimed leaves. Preparation never receives `Proxy`; runtime supplies narrow execution contexts and never matches protocol config variants or `ResolvedLeafOutbound` outside the inventory/adapter boundary.
- Legacy managed-stream adapters convert protocol-owned connector metadata directly into the runtime's `ManagedStreamConnectorFlow` with `From`/`Into`. Do not restore intermediate Parts/FlowBuild traits or a second conversion model; protocol-private cache identity remains protocol-owned.
- Ordinary SOCKS5 UDP Flow selection uses the actual standard Datagram generation in inventory and direct runtime association execution, including single/group/fallback targets. Do not restore its `ClaimedUdpFlowLeaf`, `RegisteredAssociationUdpOperation` or `UpstreamTrackedStart` wrappers. UDP policy and strict Packet admission remain authoritative; packet-carrier and relay compatibility keep their existing ownership until separately migrated.
- Every compiled inbound selects its actual standard factory and source; unsupported or failed preparation never falls back to another binder. Factories describe cold native/task budgets, build only after confirmed StopOld and publish their actual lifecycle in the same retained host before start. The host owns listener selection, accepted fan-out, shutdown and post-accept execution; adapters do not run accept loops, call serve_inbound or spawn tasks.
- WireGuard uses a thin concrete factory over the existing protocol-owned crypto device and shared endpoint state. The standard source transfers the weak identity of its actual original UDP listener, returns Packet facts without allocating a business SessionId and registers its real wire driver as Critical in the same Scope. Packet routing consumes actual IpPacket/ReturnAssociation and captured local-address/MTU/generation facts, preserving peer/source authorization, fragments, TCP MSS and inner/outer accounting. Both Packet handoff queues are single-packet, on demand and retain pending storage across cancellation. Readiness requires both the initialized Packet router loop and the actual native receive poll (Pending or successful I/O); neither queue waiting nor task registration alone qualifies. Logical return/wire joins, original UDP and child I/O receipts remain separate gates. Concrete device assembly retains same-crypto restoration and hot-update/dependency decisions without an erased listener SPI; TEMP-WG-OUTER-UDP-01 remains the only explicitly retained exception in this domain.
- Neutral accept-loop lifecycle, TCP/QUIC connection task fan-out, and connection-error logging belong to `runtime::inbound_operation` plus `runtime::listener_loop`. Protocol adapters never run these loops. `AuthenticatedQuicInboundProfile` is only the carrier preparation bridge. Production native logical streams use the existing standard RequestMultiplexer/Stream/Datagram roles, implemented by the owning protocol and supervised by the accepted Scope. Stand-alone protocol-library compatibility helpers remain runtime-neutral and protocol-owned; they are not a listener SPI or an alternate Proxy execution path. The old proxy-local native multiplexer and QUIC accept loops are removed. Keep existing frame-oriented `InboundMuxServer` / relay contracts; native QUIC streams must not be forced through a Mux.Cool reader or u16 stream IDs.
- Accepted inbound TCP/UDP/MUX route bridging lives under `runtime::inbound_route` after protocol accept/authentication is complete. Protocol-owned handshakes deliver standard AcceptedRequest facts and replies to the actual accepted Scope; adapters never retain Proxy or execute listener lifecycle themselves.
- Qualified VLESS literal QUIC/H3/Hysteria inbounds consume the actual canonical MetadataDatagram provider in their existing listener Scope. The source transfers a sealed incoming before awaiting TLS; the host publishes an actual Carrier origin without fabricating TCP/UDP admission. Match connection facts against the original metadata endpoint, share the finite child group with declared associations, and retain exact Quinn joins, explicit driver reception, sealed user/view return and original provider receipts separately. H3 requests and body workers run under the real accepted caller. Only explicitly declared internal tasks receive the actual registrar; taskless factories keep without_tasks. Noise/XDNS/XICMP decorators on qualified VLESS carriers use inert transport preparation and the same original Metadata user/driver ledger, with distinct mask origins. Confirm consumer/user return and Quinn joins before stopping mask drivers from inner to outer, then confirm original views and native provider receipts. Carrier ICMP parent cancellation fences new acquisition; its actual retained provider revokes native I/O after consumer drain. Never close a decorator underneath a still-running Quinn driver or interpret its induced BrokenPipe as successful cleanup. Qualified Hysteria file and reverse-proxy masquerades use the same standard source: file sessions retain actual native controllers and blocking jobs; origin streams use the existing declared InboundTargets provider and accepted Scope. Other unqualified combinations retain their existing compatibility ownership; this is not completion of the whole listener migration.
- Hysteria2 uses its actual protocol-owned ComponentFactory/InboundSource, authenticated RequestMultiplexer and standard Stream/Datagram replies. Preserve the existing literal QUIC bind requirement, H3/password and legacy ALPN/HMAC authentication, bandwidth negotiation, Salamander and UDP session/fragment semantics. Its optional HTTP/HTTPS websites use standard TCP sources in the same component, with separately retained original native controllers and accepted-task receivers; hostname lookups require actual Scope joins. Pure website continuations use Control without business identities. H3 classification, HTTP/H2/request tasks and file/origin providers run under the actual accepted caller; declared TCP/Unix origin streams never fall back to an unowned connector. Retired adapter listener, authenticated-QUIC/group operations and proxy-local QUIC accept loops must not return. Stop requests and logical returns remain distinct from original Metadata/TCP/file/origin receipts and Scope joins; partial auxiliary bind failure blocks replacement until all acquired originals are confirmed closed.
- Qualified HY2 outbound root/first-Datagram paths use the same protocol-owned PoolFactory, authenticated generation and original QUIC/Metadata owner through existing Stream/Datagram/Packet roles. DNS, network, full profile and real preparation-pass identity fence reuse. Start prepares declared CA material; recovery retains that exact prepared crypto. All actual users, drivers, Scope joins and original native receipts precede replacement. Root production must not instantiate standalone Hysteria2ConnectionPool/TCP/UDP compatibility bridges; preserved public protocol-library convenience APIs are outside this qualified host path. Do not expand prefix combinations or create another pool.
- Standard file masquerades declare one protocol-selected FileTree root and a finite on-demand session bound. Install the real accepted cleanup owner before the file actor or any blocking operation; retain the actual blocking JoinHandle across cancellation and confirm its join, the original actor Scope join, returned view and matching opaque native file/directory close receipt before releasing capacity or replacement. File view Drop only requests stop and returns custody. Root lookup is retained by the same listener owner; no second task owner or ordinary catalog qualification is implied. Scoped reverse-proxy HTTP/HTTPS uses declared InboundTargets and the existing DNS/native controller; HTTP/H2/body tasks run under the same actual accepted caller, without an independent connector, pool or executor. Selected standard paths never fall back to unowned file/network I/O. Internal conservative bounds do not complete the unified resource-limit configuration work.
- HTTP Forward uses standard `AcceptedRequest::Message`; protocol-owned request sources retain the actual keep-alive stream and frame each exchange. Runtime owns per-message identity, policy, route, shared rates, accounting, cancellation and upgraded duplex relay. Do not restore `MessageInboundProtocol`, adapter-owned HTTP body execution or route an entire business exchange through Control. A cancelled request-source wait retains its undelivered continuation; an exhausted CONNECT/Upgrade source drains the actual handed-off stream instead of cancelling it.
- HTTP literal and hostname listeners use their actual `ComponentFactory`/`InboundSource` and retained native owner directly; HTTP no longer implements `InboundListenerCapability` or prepares a legacy listener operation. The standard TCP source transfers the original accepted entry through erasure; the host publishes the real primary task in that same Scope before polling a protocol handshake. Taskless factories receive only a `without_tasks` view, including weak clones. Hostname preparation reserves one explicit host task slot in the same Scope and retains its actual blocking system lookup until real join; a returned address list is not that join. Freeze one address snapshot, preserve system order, and retry another candidate only after the failed original has an explicit safe close outcome, within the same finite native budget. No selected standard source may fall back to a legacy binder. Other listener adapters remain unfinished migration work, not additional exceptions to strict replacement or evidence that PR06A is complete.
- Built-in Direct listeners use the standard ComponentFactory/InboundSource for both TCP-only and paired TCP/UDP. The old standard-stream feature name remains a compatibility alias, not an execution gate. No Direct InboundListenerCapability or tcp_and_peer_datagram executor remains. The declared UDP original binds the actual TCP endpoint, including hostname resolution and ephemeral ports, through lifecycle start only. Native peer admission retains that weak original identity and declared finite queue/peer limits; it never fabricates a TCP accepted claim. Each peer uses the same listener Scope and actual bounded peer group, installs its retained Datagram cleanup owner before handshake, and releases its admission only after real joins, views, original egress closes and logical returns settle. View Drop or idle expiry alone cannot admit a replacement. Selected standard sources never fall back to a legacy binder; no new native registration is implied.
- The real business issuer attaches authorized controlled TCP carrier originals to the same accepted graph before native preparation. Retain exact adoption, weak physical-owner identity and actual caller witness, bounded by that owner's real finite capacity. Revocation is only a stop request; caller/driver joins, returned views and same-slot original native/users receipts are required before accepted cleanup completes. Never wait for a later dial to reap those originals or infer closure from Drop/EOF. Do not add another carrier pool/task owner.
- Logical Datagram originals remain in the actual accepted resource table, with finite reusable ordinals and the actual creator/driver TaskJoinWitness. Original provider cleanup plus the original Scope join is required before reuse. The same host observer completes cleanup when its waiting caller is cancelled; a bound but unpublished driver never borrows its creator's join proof. Historical receipt handles retain metadata only after cleanup and cannot remove a reused original. Joined logical TCP callers also retire their already registered original carrier slots through this same observer; cleanup serializes receipt consumption with final shutdown and never retires another active caller. No second task owner, registry or native-close proof is introduced.
- Standard accepted Datagram retains full per-packet facts, actual sender, protocol overhead and once-only negotiation traffic. Its protocol Tx borrows response payloads; Rx retains its original buffer/continuation across cancellation and recoverable Datagram errors. SOCKS5/mixed register the actual Critical UDP driver alongside the Auxiliary primary in the same accepted Scope, with two explicit resource custody slots. The host installs the original ephemeral UDP owner before bind, retains the actual Direct socket set and response JoinSet, and confirms original views, joins and native close before replacement. - Trojan inbound TCP/UDP/MUX uses the actual protocol-owned `component::inbound::listener::Factory` and standard InboundSource/Stream/Datagram/Multiplex. The proxy adapter only projects configuration into that source; its legacy InboundListenerCapability and listener bridge are removed. TLS/WS/gRPC carriers and Trojan authentication/framing remain protocol-owned. Reader, writer, logical requests and UDP drivers register in the same original accepted Scope. MUX connection authentication/cancellation remains observable at the logical request cap; a logical stream ending never proves native carrier closure.
- VMess/Trojan standard inbounds reuse the generic TLS/WS/gRPC carriers through protocol-owned requests. Standard gRPC source acceptance uses the scoped helper: the actual H2/keepalive/hunk futures run in one original accepted Scope task with bounded pending jobs; the returned cancellation view never issues a native-close receipt. Original MUX reader/writer and logical tasks use the actual accepted Scope, with no detached protocol listener worker. Their independent feature builds explicitly enable managed-datagram-runtime; a default feature union must not hide missing native ownership or standard Datagram execution. No proxy handle_vmess_raw/handle_vmess_ws/handle_vmess_grpc or legacy listener bridge may return.
- UDP relay-chain datagram-over-packet-path helpers (`resolve_udp_packet_path_chain`, `owned_packet_path_carrier`) in `udp_dispatch/start/` still match on `ResolvedLeafOutbound` — these model carrier+datagram protocol *pairs* (SS→SS, SOCKS5→SS, H2→SS), not per-protocol dispatch.

## Adapter subdirectory rule

- Adapter subdirectories require multiple real sibling responsibilities. Mieru managed UDP stays in `crates/proxy/src/adapters/mieru/udp.rs`; do not recreate `mieru/udp/flow.rs`. Hysteria2 and Shadowsocks may keep `udp/{flow,packet_path}.rs`, SOCKS5 may keep `udp/{flow,packet_path,upstream_association}.rs`, and VLESS/VMess/Trojan use protocol-owned standard sources without adapter-local listener bridges. Transport-owned UDP plans normalize endpoint/resume state through `ManagedDatagramStartPlan` or `ManagedStreamPacketBridgePlan`; proxy adds only runtime context.

## QUIC client security

- Shared QUIC client TLS configuration and endpoint dialing live in `crates/transport/src/quic/client.rs`. Protocol profiles select trust policy; owning adapters must preserve it for TCP, UDP and packet-path. Insecure mode skips chain/name verification only, not handshake signature verification. Protocol-owned UDP cache identities must distinguish trust policy and fingerprint.
- Hysteria2 HTTP/3 authentication header semantics and connection guards live in `protocols/hysteria2`; the generic proxy runtime must not parse these headers or choose protocol congestion policy. Use the protocol-owned capability metadata and pinned interoperability tests to verify feature parity and qualification gaps.

## Hysteria2 transport policy

- Public HY2 rate configuration uses Zero's `up_bps/down_bps` in bytes per second, with client-relative directions on both inbounds and outbounds. Do not restore a second `transport.bandwidth` configuration surface. Owning config/adapter boundaries map those fields to protocol-local send/receive settings; generic engine/runtime code must not interpret HY2 bandwidth headers.
- Protocol-neutral byte budgets and optional QUIC connection pacing ceilings belong to `zero-transport`. The proxy may associate budgets with logical connections or optional opaque principal policy keys; a panel account is never required. HY2 top-level rates map only to protocol bandwidth negotiation: never implicitly apply them as generic session defaults or QUIC pacing ceilings, which would suppress Brutal loss compensation or constrain adaptive mode. Explicit authenticated-entry budgets remain independent.

- HY2 bandwidth parsing, receive-rate negotiation, Brutal policy, authenticated connection pooling, HTTP/3 frame classification and masquerade behavior belong to `protocols/hysteria2`. Config owns serde ADTs and delegates private validation to the protocol's validation-only surface. Proxy prepares profiles and retires the protocol-owned pool on reload.
- Generic QUIC parameter materialization and HTTP/HTTPS origin carriers belong to `zero-transport`. `vendor/quinn-proto` adds protocol-neutral pacing-rate, packet-loss-count, exact packet-feedback and receive-window policy hooks plus the regression-tested close-only congestion exemption from RFC 9002 section 7.2; `vendor/h3-quinn` adds an externally dispatched stream source with prefix replay. Shared BBR sampling and execution belong to `zero-transport::quic::bbr`; HY2 owns profile-name parsing and parameter mapping. Receive-window growth and stream/connection coordination belong to `zero-transport::quic::receive_window`; vendored carriers only validate offsets, transport credits and dispatch neutral lifecycle feedback. Keep these pinned, license-preserving patches small and run their regression tests when updating them. Do not put Hysteria2 headers, frame IDs, credentials or bandwidth negotiation into the vendored carriers.
- The HY2 HTTP/3 driver owns classification of logical streams within one accepted QUIC connection, concurrent web requests and their bounded lifetime. Shared proxy runtime continues to own listener/connection task fan-out, authenticated routing, accounting and shutdown. Masquerade requests are ordinary website traffic and do not create proxy sessions.
- HY2 authenticated connection reuse covers TCP, managed UDP and UDP packet-path under one protocol-owned pool. It must isolate outbound tag, endpoint, credentials, TLS identity, transport settings and egress generation; reload retires cached connections while active users retain their guards. Never evict an actively borrowed connection as idle. Retry only before sending a proxy request, never replay business payload. Each authenticated connection owns one UDP reader and bounded session dispatch; UDP logical sessions own registration, fragmentation/reassembly and cancellation. Generic packet-path runtime must not read the same QUIC datagrams independently. Preserve inbound HY2 session IDs through the neutral client_session_id contract so same-target flows remain isolated. UDP managed-flow and packet-path caches must retain transport settings in their protocol-owned identities.

## XHTTP stream and Shadowsocks state ownership

- XHTTP HTTP/3 request bodies bridge into the same shared request/session executor as HTTP/1.1 and HTTP/2. `runtime/inbound_operation/quic_connection.rs` owns neutral QUIC listener execution and `context/transport.rs` owns per-stream route tasks; adapters only prepare the connection dispatcher. QUIC plus split-HTTP selects H3 in the protocol transport plan.
- Standard TCP XHTTP uses the same actual accepted caller for its HTTP connection, Hyper H2 executor and body/admission tasks. Preserve the existing listener session registry and HTTP/1 received-versus-H2/H3 queued packet receipts. A complete packet's already-polled reservation, finite permits and existing source publisher stay owned after its HTTP waiter ends, so HTTP/1 EOF cannot retire its primary before queue admission; no detached upload worker or standby carrier is introduced. VLESS reverse control, physical MUX and both UDP pumps use that same accepted Scope, and historical portal views cannot admit work after their original caller retires. Source cancellation/Drop requests teardown only; native closure still requires the real provider and Scope receipts. The old VLESS TCP recorded-route/optional dispatcher chain and handshake-target compatibility dialer are removed. Qualified Noise/XDNS/XICMP and Hysteria file/reverse-proxy carrier ownership is standard; VLESS no longer has a legacy listener. mKCP with REALITY and Hysteria without explicit QUIC credentials remain invalid configuration combinations; never activate them by widening source selection.
- XHTTP session/sequence parsing, bounded upload reordering, HTTP request tasks and connection lifetime live under `crates/transport/src/split_http/`. They must not parse VLESS or perform routing. Protocol-owned RequestMultiplexer sources deliver standard PendingInbound values; the actual host accepted Scope owns task fan-out. Do not restore the retired context/transport.rs detached task loop.
- Shadowsocks UDP replay retention and response-binding expiry live in `protocols/shadowsocks/src/udp/inbound/{state,lifecycle}.rs`. Flow expiry never evicts live replay records; full replay state rejects admission. The protocol responder's persistent maintenance deadline must survive cancelled reads and clean idle listeners as well as active traffic. Keep the inbound root a facade with model/codec/session/responder siblings.
- Shadowsocks UDP sender IDs/counters, response identity verification and replay windows live in protocol-owned `udp/{client,session}.rs`; wire-only helpers live under `udp/wire/`. Socket/packet-path factories create association codecs and clones share an association. Generic proxy code must not manufacture SS IDs, reset counters, or rebuild framing. `transport/udp_socket.rs` owns cancellation of its receiver when the flow is dropped. TCP2022 salt capacity, expiry ordering and owner-scoped maintenance live in `shared/replay.rs`; full pools reject admission without evicting live salts.

- `zero_core::InboundRecording` is the neutral handoff for removing handshake recording beneath protocol-owned stream codecs. Shared recorded MUX routing consumes its stream and traffic counters; it must not assume every MUX reader is a bare `MeteredStream<RecordingStream<S>>` or discard protocol codec state. The protocol maps its wrapper; transport owns the recording/metering implementation.

## VLESS encryption ownership

Config delegates to its validation-only parser. The protocol transport plans apply the cipher after opening each logical carrier and before VLESS framing; proxy adapters only forward the configuration. Encrypted MUX pools are isolated by protocol-owned profile identity and retired on reload. Vision bypass removes only the encryption layer, preserving the carrier and random header mask.
- `vendor/blake3` is pinned to 1.8.5 and adds only a byte-context derive-key constructor. Keep the original licenses and upstream algorithm; no VLESS behavior belongs in the vendored hash implementation.

- HTTP carrier `ed` parsing, deferred upgrades and header-prefix replay belong to `crates/transport/src/{http_early_data,http_upgrade,ws}`. WS first-write state and HTTPUpgrade response state must survive cancellation and stay bounded. Do not move protocol request bytes into proxy adapters to implement Early Data.

## Stream preludes and fallback selection

- VLESS fallback name/ALPN/path inheritance, HTTP prefix capture and selected destination belong to `protocols/vless::{fallback,inbound::fallback}`. The bounded parser preserves following bytes; proxy adapters do not parse headers or run accept tasks.
- TLS 1.3 authenticated raw handoff lives in `zero-transport::tls::switchable`, which consumes each complete record without prefetching the next and preserves buffered plaintext. Framed HTTP carriers must not expose the underlying TLS bypass control. TLS 1.2 never advertises a raw handoff.

## Reusable packet carriers and datagram masking

- `zero_traits::PacketSocketIo` and `zero_platform_tokio::PacketSocket` are neutral packet socket boundaries. The runtime peer listener owns accept/demultiplex/task lifetime over either native UDP or a prepared carrier. Protocol adapters never implement their own peer listener loops.
- `zero_transport::OutboundDatagramSocketFactory` may receive a connected datagram opener prepared by the runtime relay prefix. QUIC and mKCP consume that opener before applying FinalMask. Native socket methods reject a configured relay rather than bypassing it. `runtime/tcp_dispatch/relay/datagram.rs` bridges prepared packet-path carriers without unpacking protocol leaves or retaining the protocol registry.
- Standard masked mKCP peers originate from the actual Metadata carrier and enter the existing Carrier accepted graph. They are never fabricated native UDP peers or Quinn endpoints. Physical masks execute once; conversation futures run under the actual accepted caller and retain the original logical sender lease. Cancellation fences retained senders, while held aliases still block custody completion; neither cancellation nor lease return proves native close. XICMP uses the same host-assigned original controlled ICMP pool with one finite start-only grant, not a protocol bind or second owner. Ordinary catalog NativeIcmp coverage remains unqualified; this inbound provider does not open unrelated raw-IP/native registrations. Raw-ICMP wire qualification requires actual RAW receive access and cannot be inferred from ping-mode ownership/close tests.
- Bounded socket queues, port rotation, GRO normalization and mask state are shared transport responsibilities. Port hopping retains at most one previous receive socket and is restricted to the outermost native datagram carrier. Drop cancels drivers and releases queued work; pooled protocol connections must not create a registry ownership cycle.

## Traffic I/O observation

- Raw-IP output retains opaque per-flow provenance through `zero-stack::packet_output`. Count role TX at actual device acceptance, role RX at correlated return boundaries, and the shared endpoint/global device once. - Local discard reasons stay fixed and bounded in `zero-traits::PacketDropReason`; consuming owners record actual discards through `IoObserver`, never retryable backpressure or observation-only pressure. Engine projects reasons and retains reset baselines in its existing traffic registry.
- Optional host interface statistics are read-only platform facts (`zero-platform-tokio::network_statistics`). Proxy's existing sampler ingests them; Engine owns separate `host_interface` scopes and the `host` plane. Do not attribute interface-wide counters to endpoints/peers, sum them with Flow/Inner/Outer, or modify system network settings while observing. Host sampling uses the existing bounded event log with `stats.host_interfaces_sampled`; legacy traffic pages/events retain their supported scopes.

## Mixed TCP role migration

- Mixed TCP relay preparation selects the ordinary Stream suffix after the last unmigrated node directly from the actual component plan, without a TCP claimer for standard nodes. An unmigrated pool retains its entire shorter compatibility prefix until actual carrier borrowing and closure qualify; request-bound Stream roles are not a substitute for that persistent owner. Standard relay hops retain weak actual component-generation references, and retained reconnects check the current actual owner as well as static dependency facts. Missing, revoked or replaced selected standard owners cannot fall back to a legacy executor.
- Obtain the standard hop's host role before polling its selected compatibility prefix. The one-use prefix bridge grants no root dialing, Datagram, controlled borrowing or native close receipt, preserves actual request identity and error sources, and never invents native prefix RoleIds. A possibly submitted prefix makes failure non-replayable. Unknown endpoint observations stay unavailable. Keep the host's confirmed StopOld-before-BuildNew transaction and existing production admission gates.
- Ordinary socket and Direct compatibility preparation reuse their existing executable operation objects rather than introducing another claim wrapper. Source-relative, pooled and UDP/device-prefix legacy callers remain explicit migration debt; do not advertise them as fully migrated or introduce a second protocol SPI.
- Socket and transport TCP compatibility execution each retain one owned operation implementing both connect and relay contracts. TCP transport operations own the actual protocol leaf directly; the remaining `PreparedTransportLeaf` is managed-UDP-only. Mieru uses the common socket executor's lazy carrier handoff, with pool lookup, identity and reuse owned by its existing protocol pool. Do not restore adapter-specific prepared relay executors, relay-claim closures, borrowed-operation wrappers, or eager prefix opening on a pool hit. The runtime attaches I/O observation once, and pool-open failures retain their original typed source. These simplifications do not qualify new native ownership or relax confirmed replacement gates.

- Rejection recovery drains the failed candidate's actual retained bind reservations before rebuilding last-good components, TUN or DNS resources. Only an original physically closed and published fault from the finite pre-existing identity set permits re-entry; incomplete cleanup blocks recovery acquisition. Batch retirement must not hide an incomplete owner behind an earlier complete fault.
- SIP003 readiness retains one pending TCP probe while observing the actual Child's exit. A dead child ends readiness without waiting for the connect deadline; the plan retains the original failure and reaping owner and never respawns in place. Failure fixtures establish pending readiness explicitly and consume the real child's exit; no synthetic successful TCP probe is allowed.
- Source-relative TCP session projection uses the actual standard role when qualified, including the protocol-owned HY2 authenticated pool. Do not restore `SessionTcpHandshake`, `SessionTcpConnectOperation`, `ClaimedSessionTcpLeaf`, preparation closures or session claim helpers. Remaining unqualified UDP/device-prefix bridges retain explicit migration debt and original ownership gates.
- VLESS/VMess/Trojan TCP compatibility projection materializes protocol leaves once from the actual configuration source at the adapter boundary. The same generic transport operation holds the cold result and executes the selected owned leaf; errors stay deferred until TCP selection. Do not restore `ClaimedTransportTcpLeaf` or source-materialization closures retaining an adapter runtime. Their protocol-owned MUX views use the same actual adapter pool with outbound-owner and complete static transport isolation, shared by TCP/UDP; scope creation opens no sockets or tasks. Scope/cache eviction is not native close evidence, does not qualify production resource factories and must not relax confirmed replacement gates.

- Native VLESS/VMess/Trojan MUX preparation returns one inert physical read/write/idle driver; only the actual roleless pool owner registers it in its real TaskScope. Standard Stream roles bind that exact dependency generation and report the original through existing `UpstreamTransport::observe_carrier_origin`; never add a parallel origin/endpoint contract or fabricate an origin from addresses. Logical stream custody, actual driver join and original native close are separate gates. Native entries survive compatibility cache eviction and are reclaimed only on confirmed owner closure. Fenced Datagram TX/RX and the original control view retain one transferred-user lease until actual return. The execution owner consumes a complete original logical close report and then returns the control view; a complete report alone does not retire a still-held capability. Pending, cancelled, failed and interrupted closes retain that same owner. User return never substitutes for native or Scope evidence. The private actual-Proxy background assembly has literal-root Stream and Datagram roles over that same physical pool. Native standard Datagram execution preserves complete protocol packets, uses one bounded physical FIFO with eight data frames and at most 32 retained logical close positions, and starts no logical upload/receive task. END has a reserved position in that same FIFO, so it cannot overtake accepted data or fail just because data filled its budget. Its TX/RX views and retained logical control keep actual physical custody until return; logical close reports release only, never original native or driver closure. Trojan MUX grants only fixed-target raw UDP and rejects unsupported empty packets. Full ordinary MUX Datagram production registration stays closed until business dispatch, accounting and remaining ownership qualify; qualified first-prefix Stream admission follows the narrower rule below.

- Ordinary VLESS/VMess/Trojan MUX root-prefix admission is limited to the qualified literal/default-dial VMess gRPC Datagram relay subset. VLESS requires explicit equal XUDP/MUX concurrency; ordinary UDP is never silently converted to XUDP. The protocol factory declares Stream-only roles; compatibility UDP delegates its existing codec to that same physical native pool. Lost/retiring owners and prior legacy exposure cannot become cold through view eviction; only confirmed original closure removes native admission state. Physical/task ceilings are on demand and optional; never spawn a second compatibility pool after native admission.
