# 云端任务 PR 说明模板

标题写最终职责和行为，不写“完成全部重构”。A/B 的 base 固定为 `codex/v003-cloud-integration`。

## 问题与结果

写出实际触发条件、迁移前后行为、对应 Z003 / PR / G 目标，以及本 PR 的完整职责域。说明哪些既有调用者已迁移，哪些其他职责明确保留。

## 源码与依赖

- 初始基线完整 SHA、当前 head、所依赖的 PR/接口提交。
- 修改范围、共享文件负责人、与另一实现分支的交叉点。
- 真实 owner、原始 provider、TaskScope 与标准角色的对应关系；旧接口及全部调用者的删除位置。
- 原始清理确认先于替代构建的证据；失败候选与恢复的顺序。

## 验证

| 精确源码 / 产物 | 命令或 workflow | 结果 | 失败 / 忽略 / 未执行及原因 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 不填模拟成功，不复用旧 head 冒充 |

附真实原始日志 artifact 链接、退出码和适用环境。指出定向检查、完整回归、官方互通、平台和消费者分别完成到哪一步。

## 兼容与保留债务

说明 V1 配置/API/events、CLI、FFI、客户端面板语义和公开 Rust 迁移影响。确认没有修改消费者、扩协议组合或并行资源实例。TEMP-WG-OUTER-UDP-01 保持单独未关闭；列出其他未完成实现及资格，不用模糊“全部兼容”替代证据。

## 集成与恢复

只申请进入云端集成分支。列出冲突/失败后的源码恢复范围；运行资源恢复仍需原始清理确认。禁止 auto-merge 到 develop/main，发布和部署不在本 PR 范围。
