# 主 agent M：单环境协调与集成

你是本轮唯一主 agent。先读[入口](README.md)、[基线](baseline.json)、A/B/C 任务、[后续任务](followup.md)和[验收标准](acceptance.md)。本轮 A/B/C 是三个实现 agent，上轮名为 C 的主 agent 角色不沿用。

## 冻结开工事实

1. 只连接 `zerodenet/core` 的 GitHub remote；检查实际 URL。基线 head 应与启动提示词给出的 SHA 一致，且包含 baseline.json 的 code checkpoint。若提示词尚未填写 SHA，必须解析远端 `codex/v003-cloud-r2-base` 并固定完整 SHA，不直接使用旧 `66902032` 或 develop。
2. 保留 dirty 状态和已有工作树，不 reset、auto-stash、强推或覆盖。基线不得再追加执行变动；本轮实现只写各任务分支和 integration。
3. 创建/复用同一环境的 A/B/C 独立 worktree。初始角色分支必须基于同一已确认包 head。若远端已有真实执行提交，普通接续并记录实际基线，不能重建为空分支。
4. 一次准备 Rust 1.99.0、protoc、依赖和固定互通工具；记录实际版本。若环境提供 managed-cloud 技能先读其规则。不要复制本地凭据、绝对路径、缓存或临时日志。
5. 给每个子 agent 发其 worktree、分支、任务卡、范围和完成条件。并发是源码工作，构建及对应测试由你排队，共享 target 同时只服务一个冻结源码。

## 首先完成调用者和依赖清单

在设计目录记录版本化的简洁执行进度（不提交原始日志），每条包含：现有调用点、实际角色/owner、缺少的原始转交、唯一写入人、前置提交、替代后的删除点、必要回归、状态。禁止新增通用进度框架。

- A 列剩余 DNS bare stream/packet 调用者，并向 B 提出**具体既有组合**所需的标准角色和转交能力。
- B 列全部现有未迁出站路径，先交 A/C 所需的原件前置；不能自行再做 DNS owner。
- C 列设备域实际 owner 与 B 的借用边界，将 TEMP-WG-OUTER-UDP-01 的既有字段/分支/测试明确圈出，只保留不修改。
- 该清单冻结的是当前能力，不以增加组合来扩大任务。不使用 Unsupported、新必填配置或保留第二兼容池掩盖迁移缺口。

## 共享文件和契约

遵循入口的文件所有权。收到共享缺口时，先确认既有标准角色是否已表达；确需补齐时由你唯一提交最小中立变化和真实调用者适配，不添加协议 SPI、空 marker 或万能 context。

`register.rs` 的普通登记、`inventory/service*`、公共 tcp service、runtime/catalog/slot、platform/transport、配置预算和全局测试守卫由你串行整合。子 agent 可以给出补丁建议，不能在自己分支与其他 agent 同时改这些文件。你提交前置后通知精确 SHA，让依赖分支普通合入；分支缺少真实生产装配时不能让其只测私有 assembly 后标完成。

本轮“普通登记保持关闭”的历史限制只可在对应完整所有权、执行和回归齐备后，由你同步更新工程规则和登记；不能一键开启所有工厂，也不能把永久保留关闭状态算完成。

## PR 和合入顺序

- 所有 PR base 是 `codex/v003-cloud-r2-integration`，不是 develop/main 或基线。真实差异形成后创建 Draft PR；基线同 head 的预置空分支不创建空 PR。
- 使用[验收标准中的 PR 交付表](acceptance.md#pr-交付表)，分别记录接口/调用者删除和剩余边界。
- B 的共享原件前置优先合入，A 更新到该 integration 后完成 DNS 端；C 独立部分可早合入，依赖 B 的部分必须记录明确顺序。不能仅将三个独立通过的分支称为组合通过。
- 只有你可以普通合入 integration。不要用 ours/theirs 覆盖冲突，不重写 agent 已依赖历史，不开启 develop 自动合并。
- 每个首波 agent 完成后，按 followup.md 转交控制或预算任务并给独立分支。继续在同一个环境、复用空闲 agent，不要在 A/B/C 之外再同时启动额外实现 agent。

## 验证与最终交接

开发只跑受影响的必要定向；变更使旧证据失效时才补相应回归。重用同一冻结源码的已编译二进制，不把旧输入结果冒充新源码，不反复跑全量追求偶然全绿。

所有计划中的实现稳定后，你统一执行一次最终候选检查，完整失败先保留和归因；修复后只重跑受影响项，新的源码不能继承不适用的旧资格。必要时最终重新冻结统一资格组，明确它与原失败源码的差异，不能扩 timeout、删测试、取消真实 await 或弱化原件断言。

交付必须包含：完整候选 SHA、所有 PR/提交和依赖、逐域关闭与未完成清单、旧链归零检索、源码摘要、精确命令和结果/失败/忽略、云端与本地资格分界。原始日志上传 CI artifact 或放仓库外；任务包不能依赖原本地日志文件存在。

实现缺口、环境待验和 TEMP-WG-OUTER-UDP-01 分开报告。旧 FinalMask 并发异常及早期模式夹具超时保留历史诊断，没有新证据不得写成已修复，也不通过扩展组合去追逐它们。

最终只推送候选供本地验收。不得合入 develop/main、发版、部署、修改消费者或用户系统网络；发布和正式集成仍由用户决策。
