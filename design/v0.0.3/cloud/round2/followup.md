# 第二波：控制观测与生产预算

这些属于原计划剩余实现，不是新增目标。首波 A/B/C 交付或释放出明确独立空闲角色后，由 M **复用同一环境中的空闲 agent** 执行；总计仍为主 M 加最多三个实现 agent。不能以“后续”二字从本轮交接清单消失。

## 控制/订阅与独立资源

分支 `codex/v003-cloud-r2-control`，PR base 为 `codex/v003-cloud-r2-integration`。对应 G8 及交接中明确保留的控制/存储边界。

M 在派发前把具体文件从自己的共享范围独占转交给一个空闲 agent：`src/ipc/`、`src/http_adapter/`、控制服务装配、`crates/grpc/`、适用 Engine 事件/主体验证和 quota 持久化子模块，以及这些路径的必要测试。`crates/api` 的公开 schema、FFI ABI、CLI 语义保持；公共 runtime/task/provider 缺口仍由 M 唯一提交。

交付内容：

1. 核对控制 HTTP/IPC/gRPC 服务器、订阅本体和事件输出的真实原件、任务和退出责任，迁完 abort 后丢失原件的旧链；取消只发 stop，保留实际 join/close 确认。
2. 初启控制面 cert/key/CA、独立 quota inspect、principal quota lease/后台持久化沿已有配置与源所有权收尾；不把已完成的热配置 Source 事务另实现一遍。
3. 控制 ACK、revision、快照、事件顺序/重放、身份撤权和流量结算保持既有投影。公开控制入口不新增第二命令 API，也不写面板方言、业务模型或消费者适配。
4. 逐一迁完真实调用者后删除旧执行/持久化分支。普通 Engine-only/FFI 不自动启动完整 Proxy。

必要回归覆盖实际订阅连接挂起时取消、慢/断连接收者、原任务异常与退出、控制操作超时后的最终 ACK、持久/临时区别、quota/流量结算边界。匹配原件关闭和 Scope/JoinHandle 结果独立确认；同一产物的 GUI/面板完整资格另列，不能以改消费者取得通过。

## Z003-07 生产预算

分支 `codex/v003-cloud-r2-budgets`，PR base 同上。M 在实际 owner 稳定后转交一名空闲 agent；A/B/C 必须先提供各 owner 的当前额度、任务/队列/字节消耗、释放门槛和配置身份影响。共享 config/投影文件只有一名当前写入人，M 不与其并行编辑。

将适用资源上限接入既定配置管理，保留保守默认、按需分配与旧省略字段导出形状；不新建通用调度框架，不预建双资源实例。已有 native DNS 的 16 内部额度不等于完成全部生产配置；已有可选 pool/file/UDP 上限也不能重复算成果。

预算覆盖实际任务、native sockets/metadata、pool/逻辑资源、队列及字节等适用 owner，作用域/总计口径明确；配置变化经过同一宿主事务和原始清理屏障。容量不足拒绝新增，不驱逐活跃业务、有效 replay/security 历史；空闲与旧代际回收必须等待真实使用/任务/native 清理，不以年龄或 Drop 替代。

必要回归：默认兼容、省略字段、边界/耗尽拒绝、按需不预分配、独立 owner 不借额度、配置替换失败恢复、活跃和安全历史保留、确认清理后回收。1 CPU/1 GiB 实机的 RSS/FD/任务/吞吐/延迟与恢复退出属于独立压力资格；实现通过不冒充压力通过。参数根据现有所有者和实际证据确定，不猜一套大而统一的配置模型。
