# 标准契约总表

标准由数据类型、行为接口和可验证的前后条件共同组成。并非每个模块都需要一个 trait；开放组件使用 trait，纯计算和固定内部状态优先使用普通类型及函数。

| 契约 | 输入与输出 | 失败和所有权边界 |
| --- | --- | --- |
| ComponentFactory.build | 自有已验证 Options 与显式依赖，返回组件和实际角色 | 有资源副作用的构建在旧实例确认关闭后执行；失败先清理候选，再恢复旧实例 |
| InboundSource.accept | 接入载体，返回待握手单元；握手交付标准请求 | accept 取消不得丢失已交付单元；握手状态归协议 |
| RouteEvaluator.evaluate | 固定代际的请求事实，返回决定或 NeedFacts | 不产生网络副作用；编排限制补充事实循环 |
| PolicyEngine.admit | 请求身份和策略，返回准入凭证或拒绝 | 凭证管理配额与取消关系，执行器不能伪造 |
| SessionExecutor.execute | 已准入请求与路由决定，返回完成事实 | 负责转发、背压和业务结算，消费单次请求 |
| StreamOutbound.connect | 目标、调用上下文与载体服务，返回可用流 | 保留延迟响应语义；出错说明已产生的发送副作用 |
| DatagramOutbound.open | 目标约束与载体服务，返回收发会话 | 协议拥有关联与复用；单一接收者，关闭影响范围明确 |
| PacketOutbound.open | Packet 路由与回程上下文，返回完整 IP 通道 | 回程验证与缓冲交接明确；不隐含可执行的 Flow 转换 |
| NetworkService.open | 端点、硬拨号约束与资源范围，返回 I/O | 不能撤销约束重试；具体 I/O 归调用者或显式共享资源 |
| DnsService.query | 名称或查询、角色、策略与截止时间，返回解析事实 | 上游路径受约束；取消与缓存提交条件明确 |
| ResourceLifecycle | 准备、就绪、撤销和 shutdown | 宿主控制范围，组件确认自己的任务及 I/O 退出 |
| RuntimeHost.apply | 候选配置、临时或持久模式、预期当前版本，返回应用结果 | 整次成功或失败；受影响组件停旧再建，失败恢复不伪装成功，控制面保留 |
| Observation.record | 事件身份与明确计量事实，返回接收或背压结果 | 事实与采样策略分开；可靠事实遵守持久化和 ACK 义务 |
| Control.query 与 command | 领域命令或查询，返回领域结果 | 外部鉴权在入口执行，内核仍校验语义与并发条件 |

调用上下文只有本次操作需要的取消、截止时间、代际或观测句柄，不包含任意服务查询器。需要日志或网络的组件在构造时显式取得对应服务，不再通过执行上下文找回整个内核。

生命周期与管理能力独立于数据角色。Endpoint 的一份资源可以提供多个数据角色，但不会因此生成多个生命周期所有者。

# 配置构建与实例契约

## 三种对象

配置描述、可共享的组件实例和单次会话分别拥有不同生命周期：

```text
ConfigDocument
    -> ValidatedConfig
    -> PreparedUpdate（差异、构建计划、资源预算、补偿记录）
    -> 关闭受影响旧实例并确认释放
    -> 按依赖顺序串行构建替代实例并检查就绪
    -> ActiveGeneration
              |
              +-> 创建业务会话
```

ValidatedConfig 只证明配置语义、引用和所选能力组合有效，不证明端口可绑定或上游可达。PreparedUpdate 保存有界的已验证配置、差异、构建计划、预算和补偿记录，不持有第二套运行实例、连接池、后台任务或设备。受影响旧实例确认关闭并释放资源后，才执行替代实例的有副作用构建。ActiveGeneration 是整次应用成功后的生效视图，由宿主发布。

配置标准约定：

1. 外部 V1 配置继续接受当前字段、默认值和协议名称。

2. 公共配置负责结构、tag 引用、监听冲突等系统检查；协议拥有私有配置类型、解析与身份、密码、cipher、密钥等校验。统一解析校验入口、字段路径和错误分类，协议私有字段变化不得向通用运行层增加协议分支。

3. 公共 ADT 到协议自有配置只做一次明确转换；source_dir 与路径解析在准备阶段完成，不能每次 connect 再读取原始配置字符串。

4. 准备阶段只进行有界规范化、差异计算、文件检查和构建计划生成；必要的规则或证书读取按预算执行，不复制完整运行资源。validate 不启动运行时、不修改运行状态。

5. 工厂只接收自己的配置、必要服务和资源范围，不接收完整 RuntimeConfig 或 Engine。

6. 公开描述符保留协议基线、成熟度和限制；实际运行能力来自本次实例，不由另一套空标记重复声明。

现有配置枚举只作为 V1 兼容及分阶段迁移的适配层，协议私有强类型配置是最终归属。注册边界统一解析、校验和工厂调用；运行路径只消费已验证配置构建的能力对象，不使用 JSON 或 Any 恢复协议类型。协议内部调整留在协议包内；引入标准无法表达的新公共能力时，需独立评审契约。静态配置默认不可变，变更通过停旧再建替换，未变化实例复用；限速、撤权等动态控制走独立标准接口。

## 实例与角色

实例管理器用 ComponentId 标识资源；InboundId、OutboundId 和 EndpointId 表示可调用角色。Endpoint 可以把多个角色绑定到同一资源。生命周期只由资源所有者执行一次，防止同一 WireGuard 设备因入站和出站各自创建而重复绑定或互相关闭。

不重新引入总 ProtocolAdapter trait。标准按角色提供真实行为，组件集合记录可选角色与生命周期句柄。普通出站无需实现入站、UDP、Packet 或设备管理空接口。

# 入站与通道契约

## 入站交付

接入组件可以使用公共 listener、QUIC 或原始 datagram 设施，并拥有协议内部状态。宿主管理资源范围和就绪门，会话执行器拥有业务路由与会话任务。

标准把接入与握手分开：接收一个连接或逻辑子流后，由受限并发执行握手。一个慢握手不能阻塞同连接的其他逻辑流或整个 listener。

| 请求种类 | 协议交付 | 内核执行 |
| --- | --- | --- |
| Stream | 元数据、目标、字节流与响应处理器 | 准入、路由、连接与转发 |
| Datagram | 元数据和保持报文边界的收发会话 | 每个逻辑流的路由、统计与限制 |
| Packet | 完整 IP 包、接入身份和回程上下文 | Packet 路由或经验证的转换 |
| Control | 协议拥有的无业务目标控制会话 | 资源准入、认证后的取消与生命周期 |
| Fallback | 选定目标信息和可重放数据 | 按约定执行 fallback 与计量 |

RequestMetadata 记录来源、可信身份、原始目标、透明代理信息及协议事实，不混入路由缓存或 API 展示字段。内核分配 SessionId；协议自己的 request 或 stream ID 保持独立。

协议响应处理器接受建立成功、阻断、上游失败等标准结果，并生成自身客户端响应。成功结果携带协议需要的绑定地址等事实。每个请求只完成一次响应；取消不得重复交付已接收请求。

现有 InboundClientResponse、InboundControlSession、fallback 和 stream/route multiplexer 契约保留有效职责。帧式 MUX 与原生 QUIC 逻辑流不必使用同一种底层 reader 或 u16 标识，只统一最终业务交付。

## 通道语义

| 通道 | 基本操作与约束 |
| --- | --- |
| Stream | 以 Tokio AsyncRead/AsyncWrite 表达双向字节读写、刷新、半关闭、EOF 和 I/O 错误；握手后加解密及 framing 状态由协议流对象持有 |
| Datagram | 显式发送、接收和关闭的数据报会话；发送含目标，接收含来源；声明固定或多目标约束，保留完整报文边界 |
| IpPacket | 独立的完整 IP 报文通道；明确 MTU、地址条件、回程归属和缓冲交接，不伪装为普通 UDP 或字节流 |

只用 Send 表达跨线程移动，不默认要求每个通道 Sync。数据报接收端默认单一消费者；若并行收发需要拆分，返回独立发送与接收角色。共享传输上的逻辑通道关闭不得关闭其他会话。

超长报文、接收缓冲不足、队列满、关闭与可恢复错误要有确定语义。任何丢弃均进入约定的 drop 观测，不以悄悄截断冒充完整报文。

# 出站与上游载体契约

出站行为的逻辑签名如下，名称为目标设计，不是已发布 SDK：

```text
StreamOutbound.connect(target, request_context, upstream)
    -> Stream

DatagramOutbound.open(target_constraint, request_context, upstream)
    -> DatagramSession

PacketOutbound.open(packet_context, upstream)
    -> IpPacketSession
```

协议实例拥有握手、加解密、framing、控制连接、连接池和内部复用，向调用者交付标准通道；内核统一执行公共转发、背压、限速、计量与取消。此决定不采用把整个业务会话交给协议的通用 Process 作为默认边界。TCP 流可以在远端响应仍待验证时交付，延迟验证由协议流包装器完成，必要的客户端响应、错误阶段和就绪事实通过中立控制契约表达，内核不读取私有响应。通道包装不要求另起任务、建立内存管道或复制缓冲；协议内部用具体类型与泛型，异构边界集中类型擦除。MUX、原生 QUIC 的共享连接和子通道生命周期仍按各自语义管理，不强制全部转换成普通字节流。

UDP 会话本身提供收发行为，不再交付 resume 后由全局 handler 扫描识别。会话可以共享协议内部的底层连接，但业务流统计、取消和身份仍独立。UDP 连接暂时脱离与显式结束分别表达；continuity key 保持由协议验证后产生、由内核按接入和主体隔离，不能跨身份复用。

## 上游载体

UpstreamTransport 提供到协议端点的 stream、datagram 打开能力与所需解析。它绑定已经选定的上游链、DialPolicy、网络出口与配置代际。协议可以为复用、重连或双流 carrier 多次打开载体，但不能绕过约束自行 direct。

直连和链式代理调用同一协议入口。不同上游前缀提供不同的 UpstreamTransport；协议自己选择所需载体。载体组合先验证能力，无法执行时返回 Unsupported，不能静默改变目标或链路。

连接池身份至少区分协议配置身份、认证和信任策略、上游前缀、拨号策略及相关代际。协议构建私有部分，公共设施追加自己的隔离维度；内核不读取密码或 cipher 来拼接协议缓存键。

## Packet 与转换

路由先确定目标与模式，公共规划器在该目标内部选择满足条件的路径。Stream、Datagram、IpPacket 是通道语义，不是所有协议都必须实现的功能列表。

Packet 到 Flow 只转换受支持的流量；Flow 到 Packet 需要可用地址、MTU 与关联回程。原生 Packet 支持不自动证明转换可执行。转换器由 Stack 等公共设施实现，端点提供中立条件，不能把 proxy 私有 PacketFlowAdapter 暴露给协议。

ICMP 不新增一套 Flow 能力。auto、packet、flow、translate 的现有约束及源地址行为保留；回程关联和显式源地址转换分别有清晰归属。返回无法关联时不能凭目标 IP 就认定是已有业务回复。

Packet 发送交接还要表达所有权：交接前失败保留原始缓冲，可由策略决定后续动作；交接后失败或已消费缓冲不能盲目重发。这延续现有 PreparedPacketRouteOperation 的重要语义。

# 路由 DNS 网络与公共设施契约

## 路由与策略

纯求值入口接收 RequestFacts 与固定代际的规则视图，返回 RouteDecision 或需要补充的事实集合。业务模式优先级、bypass 和规则匹配只存在一份权威实现。

路由编排执行所请求的 DNS 等异步工作，带回事实继续求值。补充事实次数与递归深度受限；规则视图和策略代际在一次决定中一致。

路由结果使用目标 ID 和中立约束，不包含 Vless、Trojan 等具体变体。组和健康选择属于领域策略；执行器通过选定的实例能力连接。direct 的目标语义留在领域层，实际系统拨号使用 Network；block 不构造网络连接。

## DNS

DNS 服务提供查询与解析接口，拥有 dispatch、缓存、fake-IP 及状态恢复。查询带有明确角色与超时，区分业务目标、协议服务器和 bootstrap 解析。

DNS 上游经注入的网络或出站契约发送。域名形式的代理服务器和 DNS 出站形成依赖时，必须配置或构建可证明不递归的 bootstrap 路径；不能在失败时偷偷退回系统解析。

网络代际变化时，DNS 底层连接按其真实出口身份失效。fake-IP 的映射、逆向恢复和持久化语义独立于协议重构，保持旧客户端行为。

## Network

Network 服务实现物理接口选择、源地址、地址族、DNS 后的候选拨号、socket 绑定和网络变化通知。DialPolicy 的硬约束不得因重试被丢弃。

Network 用明确代际通知依赖设施，防止旧网络上预建的连接在新代际发送。会话网络事实反映实际拨号结果，不由协议名推断。

## Transport 与 Stack

TLS、WebSocket、gRPC、H2、QUIC 等作为通用 carrier；协议专有握手、协议流计划与复用状态归 owning protocol。通用 transport 不依赖 RuntimeConfig、ResolvedLeafOutbound 或业务策略。

Stack 的 packet 解析和重写保持纯函数边界，连接生命周期消费这些函数。TUN 和原始 IP 设备通过标准通道参与路由；平台管理负责设备与路由回收。公共设施允许复用，不要求每个协议经过同一套内部 manager。

# 路由网络与发送执行规格

## 一次业务请求的执行顺序

| 顺序 | 内核操作 | 协议操作及禁止事项 |
| --- | --- | --- |
| 1 | 接入端口、源端点和握手任务先执行有界准入 | 解码载体、协议握手及认证；未认证流量不能无限创建任务 |
| 2 | 接收标准请求及认证事实，建立撤权取消关系和主体准入 | 控制连接与 masquerade 不伪造业务目标或普通代理会话 |
| 3 | 固定本次规则与模式求值视图，恢复目标语义 | 已命中 fake-IP 必须按已有映射还原；缺失映射不能把合成地址当真实目标拨号 |
| 4 | 调用唯一纯 RouteEvaluator，按其 NeedFacts 补充事实 | 协议不重新实现 bypass、模式或业务路由 |
| 5 | 执行必要 DNS，再以同一求值视图复算 | 区分未尝试、解析失败、空结果和已解析，不能用空列表无限触发重复解析 |
| 6 | 解析目标、组和链路，检查实际 Stream/Datagram/Packet 角色与准入代际 | direct/block 的领域含义由 engine 决定，协议不插入静默 direct |
| 7 | 取得绑定上游前缀、DialPolicy 和网络代际的 UpstreamTransport | 协议通过它打开所需的一条或多条载体，完成握手并交付通道 |
| 8 | 按实际阶段调用入站响应器，启动公共双向转发 | 延迟确认由协议通道完成，不能强制等待依赖业务首包的远端响应 |
| 9 | 执行背压、实时限速、取消及内外层分别计量 | framing、加密、重连和共享池状态仍在协议内部 |
| 10 | 等待关闭、结算一次业务事实并释放逻辑许可 | 单逻辑流结束不误关其他用户或子流共用的载体 |

普通配置更新不会让已建立的连接重选路；会话只保留自身所需目标、通道和身份，不持有整份旧运行代际。限速读取内核可更新的策略状态；明确撤权取消对应业务。共享资源重建通过已确认的局部断连处理。共享载体服务多个主体时，撤销一个主体只关闭其逻辑会话；只有载体本身也被撤销或无法隔离，才按声明的影响范围处理。

纯路由求值与请求补充事实的决定仍由 engine 的单一入口产生，proxy 执行异步工作。[现有路由求值](../../crates/engine/src/runtime/route.rs#L24)。同一求值代际中的同一事实不得重复补取形成无限循环；已撤销的角色在真正建连前再检查。只有确认尚未提交协议请求且新快照可用时，才能按有界策略重新规划，不能在业务数据已经提交后换出站重放。

## DNS 与载体解析

业务域名解析、协议服务器解析和 DNS bootstrap 使用不同的查询角色。业务目标可以按配置保留域名交给远端；上游协议端点是否需要本地解析由载体及地址能力决定。协议不能为了取得 IP 绕过 DNS 服务或拨号约束。

DNS 服务以查询角色、服务器/出站身份、问题与代际记录解析依赖。发现同一未完成依赖再次进入时返回明确循环错误；缓存命中不凭空发起网络查询。构建时拒绝静态可见的 bootstrap 环，运行时仍防止经出站和 DNS 路由形成的递归。已有系统/bootstrap 解析策略是显式选项，不在失败后偷偷改用系统 DNS 或 direct。

Network 服务只执行物理出口及硬拨号要求；地址族、接口、源地址不能因重试失败而丢弃。网络代际变化只使相关出口和池身份失效，不能全局清空无关连接。协议服务器和信任身份、上游前缀、网络代际等组成隔离条件；秘密本身不进入可观测缓存键或日志。

## 发送投递与重试

```rust
pub enum DeliveryState {
    NotSubmitted,
    LocallyAccepted,
    Unknown,
}

pub struct SendReceipt {
    pub accepted_bytes: usize,
    pub delivery: DeliveryState,
}

pub struct SendFailure {
    pub error: ChannelError,
    pub delivery: DeliveryState,
}
```

LocallyAccepted 只表示本地协议/载体接受了一整个数据报或明确的流字节，不表示远端应用收到。协议没有端到端确认机制时不能制造 Delivered。Unknown 表示无法确认本次报文是否已进入外部传输，例如流载体已写出部分帧或写出后失败。Datagram 成功必须接受一个完整业务包；超过最大报文或本地容量明确不足时不得报告成功。

| 情况 | 投递状态 | 公共执行器行为 |
| --- | --- | --- |
| 参数非法、角色撤销、建连前容量拒绝 | NotSubmitted | 明确拒绝；仅按已有配置允许的策略更换候选或稍后重试 |
| 原生报文尚未提交，协议明确报告可恢复压力 | NotSubmitted | 在截止时间和有界缓冲内背压；不计为最终丢弃 |
| 本地完成接受或排队 | LocallyAccepted | 不自动再次发送同一业务包；后续故障按会话错误处理 |
| 写入部分协议帧、返回丢失或无法判断提交状态 | Unknown | 不自动重放业务数据；协议决定关闭或隔离本逻辑通道 |
| 对端拒绝、认证失败或明确结束 | 按实际阶段填写 | 不把逻辑结束当载体短暂断开，不自动复活已结束的会话 |
| 协议具有明确定义的序号和去重恢复 | 协议内部跟踪 | 可按固定上游语义恢复；公共层不再叠加另一轮重发 |

send 被取消时可能已有副作用；公共包装在无法证明未提交时取消或隔离该逻辑会话，后续调用不能从残帧中继续拼出另一条报文。等待 Future 被丢弃不能被解释为 NotSubmitted。recv 返回 Some 表示交付一次，None 表示该逻辑接收方向终止，错误保留原因；已经交付的帧不能因再次轮询重复返回。

TCP 异常重试只在协议请求提交前且策略允许时进行。UDP 的传输脱离、逻辑会话结束和协议允许的 continuity 分开，保留现有端到端关联。无通用可靠 UDP 层，无隐式业务重放，无跨出站负载重新发送结果不确定的数据。

## 错误与容量分类

ChannelError 至少包含 ComponentId/SessionId 的可选归属、Stage、Reason、Impact、DeliveryState、RetryClass 和错误来源链。Stage 为 Validate、Prepare、Dial、Handshake、Send、Receive、Close、Persist 或 Recover；Reason 区分 Unsupported、InvalidConfig、Capacity、Timeout、Cancelled、Revoked、Io、Protocol、StalePlan 和 Internal；Impact 区分当前报文、逻辑会话、组件或整个宿主。错误不泄露凭证，不靠字符串匹配决策。

连接年龄不是容量淘汰依据；业务空闲、池空闲、协议传输超时及安全窗口按已确认的分类执行。关闭原因和计量只结算一次，重试压力与最终丢弃分开。配置上限降低后先停止超额新准入，已有业务不为腾容量被主动淘汰；显式超时、撤权、重建及真实 I/O 故障仍按各自规则结束。

# 控制观测与可靠事件

内部采用领域查询、命令和事实。zero-api 持有对外版本化结构，HTTP、IPC、gRPC、FFI 等适配器负责转换。wire 特有字段与内部生命周期解耦，但不机械建立每层一份同义结构。

计量分别设置两个明确边界：业务通道记录内层业务字节，载体边界记录握手、加密和重传等实际外层 I/O。每个指标注明单位、方向、累计或增量、重置与采样语义。不能把共享连接全部流量归到任意一个业务 Session。

主体准入和配额仍由权威状态执行；遥测延迟或事件重放不能反向重复扣费或改变准入。会话终止事实只结算一次，事件通道允许的至少一次投递依靠原 event_id 幂等消费。

事件适配器继续保持核心实例身份、sequence、event_id、快照基线与增量合并、重放缺口、ACK 和状态恢复契约。采样与可靠事实的投递义务按当前既有规则保留；重构不把采样升级成隐式可靠日志，也不丢弃未确认事实。

Connector 继续只负责 zero.event.v1 的转换、过滤和可靠投递。URL 是完整接收地址，tag 是节点本地通道身份，source_id 是可选来源元数据。内核不规定面板接收路径、节点注册、订阅、计费或第二套指令 API。面板现有路径由面板自己配置。

观测回调必须受限并有背压或丢弃策略；日志与诊断不输出密码、私钥、完整凭证或不受控的 Debug 状态。
