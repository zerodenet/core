# 整体实施与最终合并规则

2026-10-19 用户追加确认：“应该推进目标是整个全部完成”“不要什么每个步骤都合并，肯定是全部完成”。本规则替代 PR00 时代的仅文档范围和逐阶段分支、PR、合入安排，不改变完整技术标准或降低验收。

- 仓库为 zerodenet/core，持续沿用 codex/v003-pr00-plan 工作分支和 Draft PR #124，最终 base 仍为 develop。
- PR00、PR01 至 PR11 及 A/B 子单元保留为 17 个逻辑实现、验证与可回退检查点，不为每项另开分支或 PR，不等待前置项合入 develop。
- 按依赖完成前置实现和必要验证后继续，正常提交及推送同一分支，记录每项起止 SHA、实际结果、失败、外部未验证项和回退边界。
- 整套实现和全部必要验收完成前不得合并。完成后先报告精确 head、G0–G10 整体证据和剩余限制，再进入最终评审；不能以计划、占位、编译或 scope 跳过代替实现与运行验收。
- PR 标题和说明随最终实际范围更新，保持明确的进行中状态。CI 结果必须对应当前 head，历史 PR00 的成功结果只证明原提交。
- 官方工具链和测试依赖按需要准备；不创建凭据或擅改安全设置，不使用用户 Mac，不修改 main，不发版或部署。
- 公开 Rust 接口允许必要迁移，但 V1 配置、zero.api.v1、zero.event.v1、GUI/面板和现有 FFI ABI 的兼容要求不变。单实例替换、候选清理确认、标准通道和保守资源约束不变。

原 PR00 完整方案可在提交 `122eb04b806da6a31495345d79d3e4f591f027b3` 追溯。本次修改的分节及原摘要记录在 [provenance.json](provenance.json)，不伪称修改后的正文仍等于原始 Page revision 7。
