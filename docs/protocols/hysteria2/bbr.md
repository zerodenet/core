# BBR 对齐范围与验收

对照版本为官方发布标签 `app/v2.12.2`，提交
`619a6f856b69fb7ee6a7a379e810e68b84004605`，参考 `core/internal/congestion/bbr`。
本批范围是自适应 BBR 的三个档位、采样和状态变化；QUIC 自动扩窗与连接复用另行推进。

## 配置与分层

`transport.congestion.bbr_profile` 接受 `standard`（默认）、`conservative`、`aggressive`。
`type: bbr` 且协议协商选择自适应算法时生效；固定发送速率仍按协议选择 Brutal。
`bbr_initial_window` 保留原有字节单位和 38,400 默认值，独立控制初始窗口，不能代替档位。
修改档位会改变协议连接缓存身份；重载沿用现有连接退役规则。

| 档位 | 启动发送增益 | 启动 / 稳态窗口增益 | 主要取舍 |
| --- | --- | --- | --- |
| standard | 2.885 | 2 / 2 | 默认行为 |
| conservative | 2.25 | 1.75 / 1.75 | 较低启动增益，修正发送过量与采样高估 |
| aggressive | 3 | 2.25 / 2.5 | 较大窗口，启动期计入 ACK 聚合 |

增益用于带宽与时延模型，并非用户限速倍率；档位不会保证固定吞吐。

配置只增加无法由初始窗口表达的档位选择，不复制官方应用配置树。
协议拥有名字解析和档位到参数的映射；`zero-transport::quic::bbr` 拥有可复用的 BBR 执行。
通用 engine/runtime 不识别 HY2 配置或 BBR 档位。

## 必须消除的差异

| 行为 | 原 Quinn 接入 | 本批目标 |
| --- | --- | --- |
| 启动 pacing / cwnd 增益 | 不可配置，启动窗口增益与官方标准档不同 | 按三档映射独立增益 |
| 带宽采样 | 相邻发送/确认时刻估计 | 保存每个包发送时的累计状态，按 ACK 批次采样，区分应用受限样本 |
| 窗口最大值与过期 | 最大样本更新路径不同 | 使用十轮三估计最大值过滤器，允许旧带宽估计过期 |
| 启动结束与恢复 | 固定轮数、恢复判断不同 | 三档停滞轮数、按轮丢包退出、启动期与稳态恢复分开 |
| ACK 聚合 | 启动期无条件增加窗口等差异 | 三档独立的聚合、过期和带宽增长后修正 |
| 保守档 | 缺少过量发送修正和采样防高估 | 实现对应状态变化及采样候选点 |
| PROBE_RTT | 目标窗口和计时方式不同 | 最小包数窗口、最小 RTT 十秒过期、持续 200 ms 并跨一轮 |
| MTU 变化 | 窗口缩放规则不同 | 按包数缩放初始/最大窗口并夹紧当前窗口 |

载体补丁仅增加中立的逐包事件：发送、确认、丢失、丢弃以及 ACK/丢包批次结束。
旧拥塞回调保持原有执行顺序；准确发送事件在每个 QUIC 包完成时产生，覆盖合包/GSO，
不把一个批次误当作一个包。BBR 算法和官方档位均不进入 vendor。

## 预先确定的验收条件

1. 同一份发送/ACK/丢包/RTT 事件输入，三档逐事件比较模式、窗口、pacing、带宽估计、
   轮数、恢复状态、RTT 和 ACK 聚合高度。官方生成参考结果，Rust 消费相同输入和结果。
   只固定 PROBE_BW 入口的随机周期位置，以消除非行为差异。
2. 专项覆盖保守档过量发送修正、ACK 聚合高估修正、窗口过滤器过期、探测和 MTU 边界；
   载体回归验证逐包标识、反馈结束顺序及包装器透传。
3. 官方二进制与 Zero 通过相同有限带宽、时延和丢包链路，比较三档吞吐、启动和排队情况；
   普通互通或一次吞吐相近不能替代状态回放。
   链路上行容量 262,144 字节/秒、每方向延迟 10 ms、队列最多 200 ms；分别关闭额外丢包及每 20 个包
   丢弃符合条件的大数据包，队列溢出也会丢包。每次上传 2 MiB，全程吞吐比限定 0.7–1.3，
   最后 512 KiB 吞吐比限定 0.6–1.4；Zero 首个 64 KiB 用时不得超过官方的 2.5 倍加 100 ms。
4. 全工作区、严格 Clippy、validation-only、分层回归及原有 Brutal/官方/sing-box 互通通过。

参考输入和 Go 生成器位于 `crates/transport/src/quic/bbr/tests/reference/`。
Go 生成器需放进固定参考源码的 BBR 包测试目录，设置 `ZERO_BBR_EVENTS` 和 `ZERO_BBR_EXPECTED`
后执行 `go test ./core/internal/congestion/bbr -run TestZeroReferenceTrace -count=1`；
`expected.csv` 必须与生成结果一致，禁止为了适配 Rust 输出修改参考结果。

载体调度仍使用 Quinn 的 pacing、ACK 生成和恢复机制，不能宣称逐包时间与 quic-go 完全一致。
Quinn 的 PMTU 黑洞恢复可能降低 MTU，共享控制器会安全缩放窗口，不复制参考实现的降低 MTU panic。

参考回放同时包含乱序 ACK、仅丢包反馈、空闲重启与 MTU 增长。样本清理使用载体的明确丢弃事件，
不复制参考实现按最大 ACK 包号猜测过期样本的回收方式；QUIC 包号空间通过中立标识隔离。

## 本地受控链路结果

2026-09-09，macOS 以固定提交的官方源码构建二进制运行十二次上传（每场景两种发送器），
六种场景均通过上述预设门槛。以下是 Zero / 官方的全程业务吞吐比；不是任意网络或长稳等价声明。

| 档位 | 不额外丢包 | 每 20 包按规则丢弃 |
| --- | --- | --- |
| standard | 1.009 | 0.978 |
| conservative | 0.896 | 1.000 |
| aggressive | 0.998 | 0.980 |

队列上限仍可能产生溢出丢包，因此“不额外丢包”不表示零丢包网络。
Linux CI 使用官方发布资产并校验 SHA-256，重复同一场景，不使用本地源码构建程序替代资产互通验收。
